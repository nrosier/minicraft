# Minicraft architecture (all in `index.html`)

- **World**: fixed-size `Uint8Array` grid (`SIZE` x `HEIGHT` x `SIZE`; `SIZE` 64, `HEIGHT` 32), indexed `(y * SIZE + z) * SIZE + x`. Block ids: `0` Air, `1` Grass, `2` Dirt, `3` Stone, `4` Water, `5` Sand, `6` Wood, `7` Leaves — `LEAVES` (7) is the highest id a world block can hold. Ids `8`-`10` (`RAW_CHICKEN`/`RAW_PORKCHOP`/`RAW_BEEF`, `MAX_ITEM` = 10) are hotbar-only food items, never written into the world grid. Water fills air up to `SEA`; low shores are sand; trees are placed on grass after terrain. `y=0` is unbreakable bedrock. Out-of-bounds below/sideways reads as solid stone (`getBlock`), so nothing can leave the map.
- **Generation**: seeded PRNG (`mulberry32`) -> 2D Perlin fBm heightmap -> column fill (stone, dirt, grass/sand on top), water fill, then trees. Every "New Game" uses a fresh random seed.
- **Rendering**: two merged `BufferGeometry` meshes (opaque solids + a transparent water mesh), hidden faces culled, per-face shading baked into vertex colors (no textures). `rebuildMesh()` must run (disposing the old meshes) whenever the grid changes. Sun/moon sprites and a wrap-around cloud layer follow the camera.
- **Day/night cycle & night darkening**: `updateSky(t, underwater)` runs every frame off `performance.now()`. A full day/night lap takes `DAY_SECONDS` (24 real minutes: 1 real minute = 1 game hour). The sun and moon trace a shared great circle (`sunDir`/`moonDir`, always exactly opposite each other) through `SKY_AXIS` (the horizon point) and straight up, so the moon is above the horizon exactly when the sun isn't. `scene.background`/`scene.fog` lerp between day/dusk/night colors (and separate underwater day/night colors) based on the sun's elevation (`sunDir.y`); fog also pulls in at night (`NIGHT_FOG_FAR` vs `DAY_FOG_FAR`). The same elevation drives `worldBrightness` (`NIGHT_BRIGHTNESS` floor): since `MeshBasicMaterial` with `vertexColors` multiplies the baked vertex colors by `material.color`, terrain/water/clouds dim just by setting `material.color.setScalar(worldBrightness)` each frame — no geometry rebuild needed. Animal part materials aren't shared, so `updateAnimals` recomputes each from the mesh's stored `userData.baseColor * worldBrightness`. Not saved — the cycle always starts at the same phase on page load.
- **Player/collision**: AABB vs. voxel grid via `collides(x, y, z, w = PW, h = PH)`, resolved per axis (x, z, then y). Water is non-solid; swimming uses reduced gravity and Space rises. Fall damage after 3 blocks (half a heart per extra block).
- **Mining/inventory/health**: `raycast` (voxel DDA, `REACH` 5) picks the target block (now also returns `t`, the hit distance, for comparing against animal hits — see Animals). Hold left click / `E` to mine (`HARDNESS` seconds per block, crack overlay); mined grass drops dirt. Breaking a block plays a synthesized sound keyed by the block's id (see Sound) and, if any of its 6 neighbors (including above) is water, the hole fills with water instead of staying air (`NEIGHBORS6`, single-block fill-in, no propagation). Right click / `Q` places the selected hotbar block, refused if it would entomb the player or if the slot holds a food item (`slot.id > LEAVES`). 9-slot hotbar, stacks of 64. Health is 20 half-hearts, regenerates 1 per 4 s; death respawns at spawn point with full health.
- **Sound**: `playSound(spec)` in the "sound" section synthesizes short noise bursts with the Web Audio API (one shared white-noise `AudioBuffer`, filtered per call) — no audio assets, zero build dependencies. `BLOCK_SOUND[id]` (bandpass freq/Q/decay, `wood` also layers a short triangle-wave knock) picks the timbre per block; `playBreakSound(id)` is called from `breakBlock`. `ANIMAL_SOUND` plays on a kill. `audioCtx.resume()` is called defensively since the context can start suspended until a user gesture — fine here since sounds only ever fire from a key/mouse handler.
- **Animals**: chickens (5), pigs (4), cows (4) spawn on grass columns (air above, not within 3 blocks of the player) whenever a world is generated or loaded (`spawnAnimals()`). Each is a small `THREE.Group` of box meshes defined in the `ANIMALS` table (size, speed, `killTime`, `food` item id, colored parts, facing -z). A handful of per-animal meshes is fine; the no-mesh-per-block rule still applies to terrain. They alternate idle/wander with random headings, use `collides` with their own size, hop up one-block steps, and avoid water. **Not saved** (save format unchanged); `clearAnimals()` disposes geometry/materials on respawn.
  - **Combat**: in `updateMining`, `rayBoxDist` (ray-vs-AABB slab test) finds the nearest animal on the crosshair; if it's closer than the block raycast hit (`target.t`), it takes priority — holding left click/`E` damages it over `killTime` seconds (same crack-overlay pattern as block mining, `outline`/`crack` reused at the animal's own size instead of 1×1×1). On kill, `killAnimal` removes it from `animals`/the scene, plays `ANIMAL_SOUND`, and adds one unit of its `food` item to the hotbar via `addItem` (same path `breakBlock` uses).
- **Controls**: Up/Down or W/S = forward/backward, Left/Right = turn, A/D = strafe (W/A/S/D are physical key codes, so Z/Q/S/D on AZERTY — don't switch to `e.key`), Space = jump/swim up, PageUp/PageDown = look up/down, 1-9 / wheel / `R` = select slot. Clicking the canvas enables optional pointer-lock mouse look.
- **Persistence**:
  - `localStorage` key `minicraft_save` = manual save (Save/Load buttons); `minicraft_autosave` = autosave every 30 s and on unload, restored on page load.
  - Save format is JSON, currently `version` 2: `{ version, seed, size, height, player: {x,y,z,yaw,pitch}, health, hotbar, selected, blocks }`. `blocks` is run-length encoded `[id, count, ...]` and validated against `LEAVES` (world blocks only); `hotbar` is `[id, count, ...]` per slot and validated against `MAX_ITEM` (blocks + food). Version 1 saves (no health/hotbar) still load with full health and an empty hotbar.
  - Export/Import use the same JSON (download `minecraft_save.json`, upload via file input). `applySave` validates everything (version, dimensions, RLE length, ids, health, hotbar) before touching game state.
  - If you change the save format, bump `VERSION` and keep validating on load.
